# Quickstart: validating demo mode

Validation scenarios for the finished feature. None of them makes a paid call, and none touches `data/telemetry.db`: demo mode is in memory by construction, and the local-mode check uses a temporary `DB_PATH`. Section D is the maintainer's paid, one-off procedure; it is not part of the agent's validation.

Prerequisites: `npm ci` done; Node from `.nvmrc`; the published recording downloaded and verified by `npm run build` (or already in `recordings/`); for section D only, the maintainer's own `ANTHROPIC_API_KEY`.

## A. Automated checks

```bash
npm run typecheck
npm test
```

Expected: both pass. The suite includes the new unit tests (configuration, origin and capacity decisions, player-only message, capture times, insight comparison, seed validation, project root, README hash) and the demo integration test, which spawns the server in demo mode against a synthetic recording and seed generated by the test.

## B. Demo mode locally (SC-001, SC-006, SC-008 to SC-013)

```bash
npm run build
DEMO_MODE=true PORT=10000 DEMO_ALLOWED_ORIGIN=http://localhost:5173 npm start
```

(PowerShell: set each variable with `$env:NAME = "value"` first.) Expected in the log: the `[demo]` start line, the build/hash/seed timings and "pronto" with the milliseconds until ready; no per-packet lines.

| Check | Command | Expected |
|---|---|---|
| Health | `curl -i http://localhost:10000/health` | `200`, `{"status":"ok"}`, `Cache-Control: no-store` |
| One session, capture dates | `curl -s http://localhost:10000/sessions` | one session, `startedAt` `2026-10-16T16:30:23.797Z`, `lastSeenAt` `2026-10-16T16:34:06.755Z`, `lapCount` 3, best `73372` |
| Laps | `curl -s http://localhost:10000/sessions/1` | laps 6 (74306, invalid), 7 (74144), 8 (73372) with the README's sectors |
| Samples | `curl -s http://localhost:10000/sessions/1/laps/8/telemetry` | 793 car telemetry and 793 motion samples |
| Revalidation | repeat the last request with `-H 'If-None-Match: <ETag from the first>'` | `304`, no body; first response had `Cache-Control: no-cache` |
| Seeded pair | `curl -s -X POST -H 'content-type: application/json' -d '{"lapA":8,"lapB":7}' http://localhost:10000/sessions/1/analysis` | `200`, `cached: true`, `Cache-Control: no-store` |
| Unseeded pair | same with an unseeded pair (or any pair before section D has produced the seed) | `503`, existing body |
| CORS allowed | `curl -si -H 'Origin: http://localhost:5173' http://localhost:10000/sessions` | `Access-Control-Allow-Origin: http://localhost:5173` |
| CORS other | same with `Origin: https://example.com` | no `Access-Control-Allow-Origin` |
| WS origin | open a WebSocket to `ws://localhost:10000/` with `Origin: https://example.com` | handshake refused, `403` |
| WS single car | open one with the allowed origin | messages with `data.length === 1`, `playerCarIndex === 0` |
| WS compression | the same connection, from a browser or a client that offers it | `permessage-deflate` negotiated (the browser's network panel shows it in `Sec-WebSocket-Extensions`); restarted with `DEMO_WS_COMPRESSION=false`, no extension is negotiated and the start log says compression is off |
| WS capacity | open 6 | the sixth closes with `4001` `"demo full"`; after closing one, a new one opens |
| WS time limit | keep one open 5 minutes (or start with `DEMO_MAX_CONNECTION_MINUTES=1`) | closed with `4002` `"time limit"` |
| Summary | wait 15 minutes | one `[demo]` summary with connections, WS/REST/total socket bytes, coach 503s and process CPU time |

Refusals at start, each with a clear message and no port bound: `ANTHROPIC_API_KEY` set; `DB_PATH` set; `DEMO_ALLOWED_ORIGIN` missing or with a path; `DEMO_MODE=yes`; `DEMO_WS_COMPRESSION=no`; the recording missing or altered; the seed file missing, malformed or for another recording; a seed entry whose insights differ beyond the tolerance (edit one number in a copy of the seed by 0.05 and point `DEMO_SEED_PATH` at it).

## C. Local mode unchanged (SC-007)

Same method as spec 001's [baseline-measurement.md](../001-realtime-replay/baseline-measurement.md), with a temporary database:

```bash
DB_PATH="<temp dir>/telemetry.db" npm run dev        # demo mode off: WS_PORT/UDP_PORT/HTTP_PORT from .env
npm run replay -- recordings/demo-interlagos-tt-20hz-laps6-8.jsonl
# then count rows in the temporary database
```

Expected: the startup log names the temporary database; 3 laps with the README's times; **2,411 of 2,411** car telemetry samples and **2,411 of 2,411** motion samples; per-packet log lines as today; the WebSocket on `WS_PORT` with 22 cars per message. `data/telemetry.db` is not opened.

Also, with demo mode off, `npm run build && npm start` resolves the database to `data/telemetry.db` at the repository root (startup log), not `dist/data/`; run it with a temporary `DB_PATH` to check without opening the real one, and confirm the log names that path.

## D. The maintainer's one-off coach seed (paid; never run by the agent)

1. In the Anthropic Console, set a monthly spending limit on the key's workspace.
2. In the maintainer's own shell, with the published recording in `recordings/`:
   ```bash
   DB_PATH=:memory: ANTHROPIC_API_KEY=<own key> npm run export-coach-seed
   ```
   The tool refuses to run without `DB_PATH`, or with `DB_PATH` pointing at `data/telemetry.db`. It prints, for each of the six pairs, either "reused" or the call's token `usage`, and writes `demo/coach-seed.json`.
3. Run it a second time: it must report six "reused" and make no call.
4. Read the six texts: the file is public once committed, so each text must cite only numbers found in its own entry's `insights` and hold nothing but coaching about the two laps. If one fails, delete that entry and run step 2 again (only that pair is called). Then hand the file to the agent, which commits it (tasks.md T064, `feat:`).
5. Remove the key from the shell. It is never set on the hosting platform: demo mode refuses to start with it.
